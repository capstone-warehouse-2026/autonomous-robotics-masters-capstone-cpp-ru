# ADR 0004: поведение `FollowPath` (G4)

Сокращения раскрыты при первом употреблении; [полный словарь терминов](../GLOSSARY.md).

ADR (Architecture Decision Record — запись об архитектурном решении). Статус: предложено группой G4; потребитель — G5 (клиент action).

## Контекст

[INTERFACES.md](../INTERFACES.md) фиксирует тип `/control/follow_path` — `nav2_msgs/action/FollowPath`, частоту 20 Гц и условие успеха (0.25 м, 0.2 рад, остановка), но не говорит, как сервер обрабатывает некорректный путь, замену и отмену задачи, потерю данных и отказ контроллера. Этот ADR задаёт эти правила, чтобы G5 мог писать клиента по документу. Тип сообщения и топики не меняются.

## Решение

### Приём задачи

- Путь задаётся в системе `map` (`path.header.frame_id`). Другая система → отказ `INVALID_PATH`.
- Путь некорректен, если он пустой, содержит NaN/Inf или две соседние позы дальше `max_path_gap` = 1.0 м друг от друга → `INVALID_PATH` сразу при приёме, робот не трогается.
- Путь из одной позы допустим: робот доезжает до неё и разворачивается.
- Используются только координаты поз и ориентация **последней** позы (целевой угол). Ориентации промежуточных поз игнорируются.
- Поля `controller_id`, `goal_checker_id`, `progress_checker_id` игнорируются: метод выбирается параметром `method: classical|learned`.

### Во время движения

- Одновременно активна одна задача. Новая задача во время движения заменяет старую без остановки (preemption); старая завершается как прерванная.
- Отмена: нулевая команда, затем result «отменено».
- Feedback 20 Гц: `distance_to_goal` — оставшаяся длина **пути** (не прямая до цели), `speed` — измеренная |v|.
- Нет одометрии или TF (Transform library — библиотека преобразований между системами координат) свежее 300 мс: нулевая команда, задача продолжается; если так 2 с подряд → `TF_ERROR`.
- Контроллер не выдал допустимую команду (MPC (Model Predictive Control — управление с прогнозирующей моделью) не решился, PPO (Proximal Policy Optimization — алгоритм оптимизации политики с ограничением величины её обновления) выдал NaN): нулевая команда; 3 такта подряд (150 мс) → `NO_VALID_CONTROL`.
- Застревание: за 10 с робот сдвинулся меньше чем на 0.1 м и повернулся меньше чем на 0.5 рад → `FAILED_TO_MAKE_PROGRESS`. Остановка safety monitor перед препятствием тоже приводит к этому отказу; решение о повторе принимает G5 (не более двух попыток восстановления, INTERFACES.md).

### Завершение

- Успех: до конечной позы ≤ 0.25 м, ошибка угла ≤ 0.2 рад, |v| < 0.05 м/с и |ω| < 0.1 рад/с.
- При любом завершении (успех, отказ, отмена) сервер один раз публикует нулевую команду и перестаёт публиковать. Удержание робота на месте — задача safety monitor (нет свежей команды → ноль).

### Выход

`/control/cmd_vel_raw` (`geometry_msgs/msg/TwistStamped`), `frame_id = base_link`, `header.stamp` — время симуляции момента расчёта. Все контроллеры проходят через общий ограничитель скоростей и ускорений, чтобы MPC и PPO сравнивались при одинаковых ограничениях привода. Ограничитель не является функцией безопасности.

## Архитектура пакета `capstone_control`

Алгоритмы отделены от ROS (Robot Operating System — программная платформа для робототехники) в библиотеке `capstone_control_algorithms` и тестируются без симулятора:

- `PathTracker` — проекция робота на путь, пройденная и оставшаяся длина, поперечная ошибка. Проекция ищется только вперёд в окне 1.5 м, чтобы на пути с петлёй робот не «перепрыгнул» назад.
- `Controller` — общий интерфейс: `ControlInput` → `Command` или «нет допустимой команды». Реализации: `PurePursuitController` (временный, до MPC), затем MPC и PPO с одинаковым входом.
- `CommandLimiter`, `GoalChecker`, `ProgressChecker`.

Pure pursuit — временный классический контроллер для интеграции с G5 и safety monitor до готовности MPC. Препятствия он не объезжает. В итоговом сравнении методом A остаётся MPC.

## Параметры по умолчанию

| Параметр | Значение |
|---|---|
| `max_path_gap` | 1.0 м |
| Допуск цели | 0.25 м, 0.2 рад, \|v\| < 0.05 м/с, \|ω\| < 0.1 рад/с |
| Застревание | 0.1 м или 0.5 рад за 10 с |
| Возраст одометрии/TF | 300 мс; `TF_ERROR` через 2 с |
| Отказ контроллера | 3 такта подряд |
| Ограничения | v ∈ [0, 0.5] м/с, \|ω\| ≤ 1.0 рад/с, разгон 0.5 м/с², торможение 1.0 м/с², 2.0 рад/с² |
| Pure pursuit | lookahead 0.6 м, замедление за 0.8 м до конца, разворот на месте при ошибке направления > 0.8 рад |

Значения задаются в конфигурации узла и уточняются по динамике TIAGo Base в симуляторе; изменение фиксируется в этом ADR.

## Открытые вопросы

- `/state/odom` и TF `map → odom → base_link` публикует G1; пока их нет, проверка в симуляторе невозможна. Драйвер `capstone_sim` одометрию не публикует.
- `/sensors/scan` (LiDAR (Light Detection and Ranging — лазерный дальномер)) в мире пока нет; он нужен safety monitor и MPC.
