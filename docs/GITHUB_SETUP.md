# Первоначальная настройка репозитория на GitHub

Сокращения раскрыты при первом употреблении; [полный словарь терминов](GLOSSARY.md).

Инструкция для владельца репозитория: выполняется один раз. Участникам команды она не нужна, им достаточно [быстрого старта](../README.md#быстрый-старт).

## 1. Организация и пустой репозиторий

1. Создать бесплатную организацию: <https://github.com/account/organizations/new>. Команды GitHub и CODEOWNERS по командам работают только в организации, не в личном аккаунте.
2. В организации создать **публичный** репозиторий без README, лицензии и `.gitignore`. Для публичного репозитория бесплатны минуты GitHub Actions и защита веток; в приватном на бесплатном тарифе защиту `main` включить нельзя.

## 2. Загрузить проект

В локальной копии репозиторий преподавателя становится `upstream` (из него забираются обновления задания), а новый — `origin`:

```bash
git remote rename origin upstream
git remote add origin git@github.com:<организация>/<репозиторий>.git
git push -u origin main
git tag v0.1.0-assignment
git push origin v0.1.0-assignment
```

Тег `v0.1.0-assignment` отмечает исходное задание, чтобы не путать его с результатами команды ([WORKFLOW.md](WORKFLOW.md)).

## 3. Команды, CODEOWNERS и защита `main`

Нужен GitHub CLI (<https://cli.github.com>) с правами на организацию:

```bash
gh auth login
gh auth refresh -s admin:org
scripts/github/bootstrap_repo.sh <организация>/<репозиторий> --dry-run
scripts/github/bootstrap_repo.sh <организация>/<репозиторий>
```

Скрипт:

- создаёт команды `infra`, `g1` … `g5` и даёт им доступ на запись (`infra` — maintain);
- заменяет `@ORG` в [.github/CODEOWNERS](../.github/CODEOWNERS) на имя организации;
- включает удаление веток после слияния PR (Pull Request — запрос на включение изменений в репозиторий);
- защищает `main`: изменения только через PR, обязательны проверки CI (Continuous Integration — непрерывная интеграция; автоматическая сборка и проверки) `shellcheck`, `make setup (ubuntu-22.04)`, `make setup (ubuntu-24.04)`, одно одобрение владельца изменённого кода; устаревшие одобрения сбрасываются при новых коммитах, обсуждения должны быть закрыты; force push и удаление `main` запрещены.

После скрипта закоммитить изменённый CODEOWNERS. Администраторы организации могут обойти защиту, поэтому этот коммит можно отправить прямо в `main`:

```bash
git commit -am "Set CODEOWNERS organization"
git push
```

## 4. Участники

Пригласить каждого в организацию сразу в команду своей группы: **Organization → People → Invite member → Teams**. Себя добавить в `infra` и в свою группу. После принятия приглашения участник выполняет [быстрый старт](../README.md#быстрый-старт).

Командой (для уже состоящего в организации пользователя):

```bash
gh api -X PUT orgs/<организация>/teams/g2/memberships/<логин>
```

## 5. Проверка

Создать ветку с любой мелкой правкой, открыть PR и убедиться, что запускаются три проверки CI, а кнопка слияния ждёт одобрения владельца кода. Первый прогон CI собирает образы с нуля и занимает около 15 минут на каждую версию Ubuntu.

Имена проверок заданы в `.github/workflows/ci.yml` и в `scripts/github/bootstrap_repo.sh`; при переименовании задач CI обновить оба файла и повторить скрипт. Если GitHub перестанет предоставлять runner `ubuntu-22.04`, убрать его из матрицы CI и из списка обязательных проверок.
