# G3. Классический метод планирования (метод A)

Сокращения раскрыты при первом употреблении; [полный словарь терминов](GLOSSARY.md).

Задание: [projects/03_planning.md](../projects/03_planning.md). Код: пакет [capstone_planning](../ros2_ws/src/capstone_planning/README.md). Метод B (обучаемая стоимость на CNN (Convolutional Neural Network — свёрточная нейронная сеть)) пока не реализован: при `method: learned` узел использует стоимость метода A как fallback и сообщает об этом в `/diagnostics`.

## Что реализовано

1. **Map fusion.** Статическая карта `/map` объединяется с последней неинфлированной сеткой G2 `/perception/obstacles` (обычно в `odom`), перенесённой в `map` через TF (Transform library — библиотека преобразований между системами координат) `map ← odom` на момент сетки. Правила без памяти между обновлениями: препятствия `/map` не стираются; наблюдаемая занятая клетка становится занятой (каждая локальная клетка проецируется 3 × 3 точками, поэтому тонкое препятствие не теряется при повороте и разном разрешении); наблюдаемая свободная клетка очищает только неизвестную клетку `/map`; препятствие, которое уехало, исчезает со следующей сеткой.
2. **Inflation и hard collision mask.** Робот — диск радиуса 0.272 м ([ADR 0002](adr/0002-tiago-base-warehouse.md)) плюс запас 0.05 м. Clearance клетки — точное евклидово расстояние от центра клетки до края ближайшей клетки-препятствия (distance transform Felzenszwalb–Huttenlocher). Клетка проходима, если она не препятствие и clearance ≥ 0.322 м. Неизвестные клетки — препятствия ([INTERFACES.md](INTERFACES.md)); режим `unknown_is_obstacle: false` оставлен для заранее зафиксированного эксперимента. Это единая маска, которую должен использовать и метод B.
3. **Фиксированная стоимость.** Стоимость метра в проходимой клетке:
   `1 + 2.0 · s(clearance, 0.5 м) + 3.0 · s(clearance до наблюдаемых препятствий, 1.0 м) + 1.0 · [неизвестно]`,
   где `s(d, band) = max(0, 1 − (d − 0.322) / band)²`. Второй член — наблюдаемая occupancy: препятствия, которых нет в `/map` (люди, другие роботы, сдвинутые поддоны), дороже статических стен, поэтому короткий загруженный маршрут может проиграть длинному свободному. Нижняя граница стоимости метра равна 1.
4. **A\*.** 8-связная сетка, шаг стоит `длина · (c(a) + c(b)) / 2`. Диагональный шаг разрешён, только если обе боковые клетки проходимы (нет corner cutting). Эвристика — octile distance, умноженная на нижнюю границу стоимости шага (1 на метр); она допустима и согласована, поэтому A\* с закрытым списком оптимален для этой стоимости. Тот же код с нулевой эвристикой — Dijkstra для проверки корректности.
5. **Отказы.** Цель в препятствии или в маске → `GOAL_OCCUPIED`; старт в препятствии → `START_OCCUPIED`; старт в маске (шум локализации, новое препятствие рядом) выводится к ближайшей проходимой клетке не дальше 0.5 м, иначе `START_OCCUPIED`; недостижимая цель → `NO_VALID_PATH`; вне карты → `START/GOAL_OUTSIDE_MAP`; 200 мс по steady clock → `TIMEOUT`; нет `/map`, свежей `/perception/obstacles` (≤ 0.3 с) или позы → явная ошибка. Ни один отказ не возвращает пустой «успешный» путь.
6. **Action `/planning/compute_path`** (`nav2_msgs/action/ComputePathToPose`). Старт — `start` при `use_start`, иначе свежая `/localization/pose`. Путь в `map`: точный старт, центры клеток с ориентацией на следующую точку, точная цель с её yaw; соседние точки не дальше 0.071 м (G4 требует ≤ 1 м, [ADR 0004](adr/0004-g4-follow-path.md)). Поиск идёт в отдельном потоке; cancel и новая цель (preemption) прерывают его. `planner_id` игнорируется: метод выбирается параметром `method`.
7. **Перепланирование при обновлении карты.** Последний успешный путь проверяется по новой сетке препятствий (не чаще 2 Гц). Если он стал непроходимым, узел сразу публикует `/diagnostics` с WARN «last path blocked … replan» и увеличивает `path_blocked_events`; новый запрос отправляет G5.
8. **Метрики в `/diagnostics`** (1 Гц): число запросов и успехов, отказы по кодам, latency p50/p95/p99 по последним 1000 запросам, deadline misses, expanded nodes, длина и минимальный clearance последнего пути, `path_blocked_events`, возраст сетки препятствий.

## Проверка

`make test PKG=capstone_planning` запускает два набора gtest:

- `test_planning_algorithms` (23 теста, без ROS (Robot Operating System — программная платформа для робототехники)): преобразования и fusion с поворотом, сохранение тонкого препятствия, отсутствие памяти между обновлениями; distance transform против полного перебора; inflation и монотонность стоимости; запрет corner cutting; все явные отказы; выход старта из маски; **A\* против Dijkstra** на 60 случайных картах 40 × 40 (по 5 пар старт–цель, с unknown как препятствием и без): одинаковый статус и стоимость с точностью 1e-9, A\* раскрывает не больше узлов, эвристика не превышает истинную стоимость, стоимость пути пересчитывается по шагам; cancel, deadline и лимит раскрытий; сценарии ниже; признак блокировки пути после обновления карты.
- `test_planning_node` (11 тестов): параметры, конвертация `OccupancyGrid`, полный цикл action с публикацией `/map`, `/perception/obstacles` в `odom` со static TF `map → odom`, `/localization/pose` (свежая и устаревшая), все коды ошибок, отмена и timeout.

## Ограничения и что осталось

- Внутренняя стоимость A не сравнивается со стоимостью B; итоговые сравнения — по внешним метрикам закрытого цикла с одним G4 (travel time, delay, completed deliveries), которые ещё не измерены в симуляции.
- Карта склада в бенчмарке — приближение по [ADR 0002](adr/0002-tiago-base-warehouse.md), а не экспорт `/map` G1; после появления карты G1 бенчмарк нужно повторить на ней и на записанном replay.
- Узел не реализует `rclcpp_lifecycle`; готовность видна в `/diagnostics` («waiting for /map»).
- Метод B (CNN-стоимость, labels задержки из rollouts, ONNX inference, ablation без истории) — следующий этап; он должен использовать ту же `CostMap`-маску и `plan_on_grid`.
