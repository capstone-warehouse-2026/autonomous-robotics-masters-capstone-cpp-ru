# G2. Нейросетевой метод восприятия

## Задача и интерфейс

Метод B восстанавливает локальную проходимость склада из синхронизированных RGB, глубины и CameraInfo. Сеть присваивает каждому пикселю класс «свободно», «препятствие» или «неизвестно». Узел переносит точки в систему `odom` и публикует сетку `/perception/obstacles` размером 200 × 200 с шагом 0,05 м. Метод A использует тот же построитель сетки. Точки с отсутствующей глубиной не голосуют за свободное место.

## Данные и обучение

Складские планировки сгенерированы в Webots. Камера Orbbec Astra даёт зарегистрированные RGB и глубину в разрешении 640 × 480. Датасет включает 900 кадров трёх обучающих планировок, 300 кадров отдельной валидационной планировки и 600 кадров двух тестовых планировок. Порог пола при разметке составляет 2 см от плоскости, верхняя граница препятствия — 1 м. Эталонные метки получены по чистой глубине и точной позе камеры. Отсутствующая глубина остаётся неизвестной.

Компактный U-Net с 488 323 параметрами принимает RGB, нормированную глубину и маску валидности в тензоре 5 × 240 × 320. Обучение выполнено в PyTorch на GPU за 30 эпох с AdamW и взвешенной кросс-энтропией. При обучении применяются изменения освещения, шум глубины, пропуски и отражение. Контрольная точка выбирается по mIoU на валидации. Модель экспортируется в ONNX и выполняется на CPU в узле C++. Тест эталонного кадра сверяет предобработку, логиты и классы с Python. [Подготовка данных и команды обучения](../ml/perception/README.md)

## Офлайн-протокол

Сравнивались две обученные версии метода B. Вторая версия обучалась на том же разбиении и с той же архитектурой при занулённых цветовых каналах. Каналы также занулялись во время её оценки. Обе версии использовали одинаковые записанные кадры и одну эталонную сетку на основе чистой глубины. Синтетические искажения применялись только ко входу. Результат `unknown` в видимой эталонной клетке учитывался как пропуск. Строка с неизвестным эталоном хранится отдельно в матрице ошибок.

Основные показатели — IoU препятствий по клеткам и доля ложно-свободных среди эталонных занятых клеток. Интервалы для разницы рассчитаны парным bootstrap по кадрам с сохранением числа кадров каждого склада (5000 повторов, seed 12345). Они описывают разброс для записанных планировок. Поднабор тонких стоек входит в набор чистых кадров.

## Результаты и ошибки

Цвет повышает IoU препятствий во всех проверенных условиях. Слабое освещение показывает компромисс. IoU выше при использовании цвета, а доля ложно-свободных клеток ниже у модели с одной глубиной. Шум глубины даёт наибольшее снижение IoU полной модели по сетке. Это согласуется с чувствительностью координат проекции к глубине. [Таблица результатов и команды воспроизведения](../ml/perception/README.md#результаты-сравнения-с-моделью-без-rgb)

На чистых кадрах прибавка IoU от RGB составила 8,62 процентного пункта (95 % ДИ от 6,60 до 10,64). При слабом свете доля ложно-свободных клеток с RGB выросла на 1,36 процентного пункта (95 % ДИ от 1,07 до 1,67).

Для разбора выбраны три кадра с наибольшим абсолютным числом ошибок указанного типа при соответствующем искажении.

| Кадр | Условие | Наблюдение |
|---|---|---|
| `test_0/frame_000238` | Слабый свет | 242 из 932 занятых клеток помечены как свободные. |
| `test_0/frame_000201` | Шум глубины | 735 эталонных свободных клеток помечены как занятые. |
| `test_0/frame_000075` | Пропуски глубины | 154 из 1225 занятых клеток помечены как неизвестные. |

Дальность считается от начала `base_link` до центра эталонной занятой клетки. Для каждого интервала [0, 2), [2, 4) и [4, ∞) м оценщик сохраняет числа клеток, предсказанных свободными, занятыми и неизвестными.

При шуме глубины доля ложно-свободных клеток увеличивается с расстоянием.

| Расстояние | Эталонных занятых клеток | Ложно-свободные |
|---|---:|---:|
| 0–2 м | 51 917 | 0,24 % |
| 2–4 м | 155 425 | 0,38 % |
| 4 м и дальше | 108 179 | 4,53 % |

## Воспроизведение результатов

Экспортируйте replay и запустите C++-оценщик для обеих моделей по инструкции G2. Для таблиц по дальности в контейнере разработки выполните:

```bash
source /workspace/ros2_ws/install/setup.bash
cd /workspace/data/g2/grid_replay
for condition in clean low_light depth_noise depth_holes; do
  ros2 run capstone_perception grid_replay "$condition.rgbd" "$condition.report.learned.csv" \
    --ros-args -p method:=learned > "$condition.report.learned.summary.csv" || break
done
```

С хоста, где установлены NumPy и Matplotlib:

```bash
python3 ml/perception/summarize_grid_report.py --out data/g2/report_b \
  --image-id "$(docker image inspect capstone-dev:local --format '{{.Id}}')"
```

В `data/g2/report_b` сохраняются кривые обучения, матрицы ошибок, интервалы, разбивка по дальности и manifest с хешами моделей и данных. Для финального отчёта G2 требуется добавить результаты классического метода на общих эпизодах, проверку резервного перехода и наблюдаемые последствия ошибок для G3/G4. Этот комплект описывает офлайн-прогоны метода B.
