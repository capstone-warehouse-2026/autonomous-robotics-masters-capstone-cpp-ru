# Данные и обучение метода B (G3)

Сокращения раскрыты при первом употреблении; [полный словарь терминов](../../docs/GLOSSARY.md).

Офлайн-инструменты обучаемой стоимости G3 на Python. Модель выполняется в C++ (`CostModel` в [capstone_planning](../../ros2_ws/src/capstone_planning/README.md)) через ONNX (Open Neural Network Exchange — открытый формат обмена моделями нейронных сетей) Runtime. Задание: [projects/03_planning.md](../../projects/03_planning.md), отчёт: [docs/G3_METHOD_B.md](../../docs/G3_METHOD_B.md).

## Идея

CNN (Convolutional Neural Network — свёрточная нейронная сеть) получает статическую карту и историю наблюдаемой занятости и прогнозирует **дополнительную неотрицательную стоимость метра** (задержку) в каждой клетке 0.2 м. A\* метода A остаётся тем же: та же hard collision mask, те же длина и clearance; член «наблюдаемой occupancy» метода A заменяется прогнозом сети. Будущие траектории агентов сеть не получает. Вне наблюдаемой области используется фиксированный prior — средняя метка обучающих клеток вне окна наблюдения.

## Вход и выход сети

Все каналы — доли занятых мелких клеток (0.05 м) в блоке 4 × 4 (`sim.pool`, в C++ `pool_fraction`; неполные блоки на краю усредняются по существующим клеткам):

| Канал | Содержимое |
|---|---|
| `static` | препятствия `/map` (в C++ неизвестные клетки тоже) |
| `observed_t-0` … `observed_t-3` | наблюдаемые препятствия, которых нет в `/map`, в моменты t0, t0 − 1 с, t0 − 2 с, t0 − 3 с (нули, если кадра нет) |
| `observed_mask` | область, которую видит восприятие в момент t0 |

Выход — `1 × H × W`, softplus (≥ 0), не больше 10. Сеть полностью свёрточная и работает на карте любого размера. Метаданные (`history`, `unobserved_prior`, `max_extra_cost`, `block`, `history_period_s`, `channels`) записаны в сам ONNX-файл, поэтому узлу нужен только он.

## Данные: эпизоды и метки задержки

[sim.py](sim.py) — синтетический склад без Webots, детерминированный по сиду:

1. **Планировка:** стены, 3–5 рядов стеллажей вдоль x или y (глубина 0.6–1 м, проходы 1.6–2.6 м), поперечный проход, 2–5 поддонов.
2. **Агенты:** 6–14 людей/погрузчиков (радиус 0.3 м, 0.4–1.2 м/с) ходят по кратчайшим путям между своими станциями и стоят там 3–25 с. Часть станций общая (точки скопления), поэтому история частично предсказывает загруженность.
3. **Наблюдатель:** робот в случайной свободной точке; окно восприятия 10 × 10 м (как сетка G2) даёт историю t0 … t0 − 3 с.
4. **Метки:** 160 «пробных» роботов стартуют в t0 по кратчайшим путям с **фиксированным классическим контроллером**: 0.5 м/с вдоль пути, остановка, пока агент впереди ближе 1.0 м или в любом направлении ближе 0.67 м; тайм-аут 90 с. Метка клетки = (время ожидания в клетке · 0.5 м/с) / метры, пройденные в клетке; клетки, где пройдено меньше 0.4 м, не размечены.

Разбиение ([splits.json](splits.json)): обучение — планировки 0–39, валидация — 1000–1009, тест — 2000–2009; по 10 эпизодов на планировку (400 / 100 / 100). Планировки не пересекаются между частями.

### Известные смещения меток (data card)

- **Контроллер и агенты упрощены:** кинематический робот с остановкой вместо MPC (Model Predictive Control — управление с прогнозирующей моделью) G4; агенты не реагируют на робота. Метки описывают задержку именно этого контроллера.
- **Смещение выбора:** метки есть только на клетках, через которые проходят кратчайшие пути; клетки у стен и редкие объезды размечены хуже.
- **Атрибуция ожидания:** ожидание записывается в клетку, где робот стоит, а не туда, где агент; сеть учит контекст вокруг.
- **Шум горизонта:** задержка измеряется на горизонте до 90 с, а история — 3 с; дальние задержки из истории непредсказуемы, большая часть меток равна нулю (средняя метка ≈ 0.14).
- **Синтетический домен:** реальные rollouts в Webots с G4 ещё не записаны; формат эпизода (`planning_replay`) позволяет подставить их без изменения обучения.

## Команды

```bash
make g3-dataset          # data/g3/{train,val,test}, ~25 мин на 4 ядрах
make g3-train            # data/g3/models/latest и data/g3/models/no_history (абляция)
make g3-eval             # замкнутый цикл A / B / B без истории на тестовых складах
make g3-model            # models/planning_cost.onnx в пакет + эталон для test_learned_cost
python3 -m unittest discover -s ml/planning
```

[evaluate.py](evaluate.py) экспортирует наблюдение каждого тестового эпизода, строит пути C++-планировщиком (`planning_replay`, та же cost map и A\*, что в узле) для каждого метода и проводит их тем же контроллером среди **будущего** движения агентов.
