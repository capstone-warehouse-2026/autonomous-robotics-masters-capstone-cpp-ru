# G5: обучение диспетчера DQN

Эта директория содержит **offline обучение**. Исполнение миссии, выбор заявки
по обученной модели и расчёт первичных итоговых метрик выполняются на C++ в
`capstone_mission` и `capstone_benchmark`.

## Воспроизведение

Команды выполняются из корня репозитория. Нужны Python 3 и NumPy 1.26.4;
GPU, PyTorch, Webots и ROS для обучения не требуются.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r ml/mission/requirements.txt
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 ml/mission/train.py \
  --episodes 1000 --seeds 0 1 2 --out data/g5/training
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 ml/mission/train.py \
  --episodes 1000 --seeds 0 1 2 --no-congestion --out data/g5/ablation
OPENBLAS_NUM_THREADS=1 python3 ml/mission/export.py \
  --training data/g5/training --ablation data/g5/ablation
python3 -m unittest discover -s ml/mission -q
```

В ROS-окружении дополнительно: `ament_flake8 ml/mission`.
Число потоков BLAS фиксируется для воспроизводимости и чтобы маленькие матрицы
не тратили время на запуск большого числа потоков. На использованном CPU обучение
одного seed занимало около 12–15 секунд; фактическое время каждого запуска сохранено
в карточке модели. Другой BLAS/процессор может изменить результаты округления.

## Алгоритм

Это обучаемый DQN, а не переименованное правило выбора. Сеть имеет структуру
`32 → 64 (ReLU) → 5`, всего 2437 обучаемых параметров. Используются:

- кольцевой replay buffer на 20 000 переходов;
- mini-batch 64, обучение каждые два перехода после 128 переходов;
- отдельная target network, обновление каждые 250 переходов;
- Huber loss, Adam (`lr=0.001`), clipping градиента;
- epsilon-greedy от 1.0 до 0.05 за первые 75% эпизодов;
- discount `0.995 ** duration_seconds`: решения принимаются с разными интервалами;
- одинаковая маска доступных действий при exploration, inference и Bellman target.

Сеть предсказывает пять Q-значений: четыре слота заявки и `wait`. После доставки
или ожидания очередь пересобирается. Активная доставка не прерывается политикой.
Неизвестные/нечисловые действия в C++ обрабатываются классическим fallback.

## Наблюдение и маска

Точный контракт находится в `spec.py` и повторён в C++ `make_observation`.
Четыре старейшие поступившие заявки сортируются по `(release_time, job_id)`;
оставшиеся сохраняются в очереди. Каждый слот содержит семь чисел:

| Смещение | Признак |
|---|---|
| 0 | время до pickup / 120 с |
| 1 | время pickup → dropoff / 120 с |
| 2 | `(due_time − now − оба времени поездки − оба service_time) / 300 с` |
| 3 | возраст заявки / 300 с |
| 4 | congestion на участке pickup → dropoff / 3 |
| 5 | накопленное число неуспешных попыток навигации в эпизоде / 2 |
| 6 | наличие заявки: 1, для пустого слота 0 |

Индексы 28–31: `robot_x / 20 м`, `robot_y / 20 м`, `loaded`, `now / 300 с`.
Пустые слоты заполнены нулями и маскируются; `wait` всегда доступен и длится
ровно одну секунду simulation time. Выбор новой заявки возможен только без груза.
Таблица времени содержит базовые оценки; текущая congestion умножает их при
построении наблюдения и исполнении. Будущие arrival events не доступны сети.

Для ablation индексы 4, 11, 18, 25 обнуляются при **обучении и выполнении**;
остальные признаки и условия остаются прежними. Это удаляет явный congestion
feature, но оценки travel time всё ещё отражают длительность маршрута.

## Табличная среда и разделение данных

Склад имеет шесть станций. Геометрия и коэффициенты объезда создают фиксированные
таблицы расстояний; скорость 0.5 м/с задаёт базовые времена. Режимы:
`low`, `high`, `bottleneck`, `blocked`, `unequal`. Во всех сценариях горизонт
300 секунд, заявки поступают до 170 секунд, обслуживание занимает 2 с на станции.

| Split | Layouts | Scenario seeds | Использование |
|---|---:|---|---|
| train | 3 | 0–999 | обучение, случайный выбор сценариев |
| validation | 1 | 1000–1009 в оценке | 50 фиксированных эпизодов, выбор checkpoint |
| test | 2 | 2000–2019 | 100 фиксированных эпизодов, только итоговая C++ оценка |

Геометрия каждого split создаётся отдельным seed генератора layout. Сценарии и
их SHA256 зафиксированы в `scenarios/manifest.json`. В `scenarios/train` лежат
15 компактных примеров; весь train-диапазон воспроизводит `make_scenario`.
Нельзя менять нормализацию или выбирать модель по результатам test.

Reward обучения: доставка +5, своевременная доставка дополнительно +3;
просрочка уменьшает reward до −3; отказ −5; стоимость времени −0.01/с,
стоимость решения −0.02, ожидание при доступных заявках дополнительно −0.05;
незавершённые заявки при завершении эпизода −2 за заявку. Это вспомогательная
цель обучения. Итоговые выводы делаются по deliveries/on-time/tardiness и другим
метрикам C++ benchmark, а не по reward.

Заблокированный участок даёт две попытки по секунде. При неудаче pickup заявка
переходит в `failed`, робот остаётся на месте. При неудаче dropoff робот удерживает
груз и больше не выбирает заявки до конца горизонта; все arrivals продолжают
учитываться. Поездка, пересекающая горизонт, остаётся незавершённой.

## Артефакты

`ros2_ws/src/capstone_mission/models` содержит:

- `dispatch_dqn.json` — checkpoint с максимальным validation return;
- `dqn_seed_0.json` … `dqn_seed_2.json` — лучшие checkpoints всех training seeds;
- `dispatch_no_congestion.json` и три ablation checkpoints;
- `learning*.csv` — поэпизодные train reward/loss и validation curves;
- `model_card.json` — параметры, seeds, длительности, SHA256, версия исходников;
- `golden.json` — наблюдения, маски, Q-значения и действия для сравнения Python/C++.
- `preprocessing_golden.json` — исходные сценарии/контекст и ожидаемые признаки,
  включая очередь длиннее четырёх и накопленные navigation failures.

Экспорт — намеренно простой **JSON MLP**, не ONNX. `w1`/`w2` хранятся плоскими
массивами row-major `[hidden,input]` и `[output,hidden]`, `b1`/`b2` — смещения.
C++ проверяет версию, размерность, длину массивов и конечность чисел, затем
выполняет два матричных умножения и ReLU. Это поддерживает полноценный C++
inference без отдельной Python/ML среды на роботе. Ошибка модели не подменяется
фиктивными Q-значениями.

Обучены три seeds по 1000 эпизодов и столько же для ablation. Выбор сделан по
validation, без просмотра test: seed 2, return 13.950; seed 0 — 12.031,
seed 1 — 13.387. У ablation seeds 0/1/2 соответственно 9.112, 10.343, 4.475.
Повторное независимое обучение seed 2 теми же командами дало побитно одинаковый
checkpoint: SHA256 `b86f66590da3591a8d1ec96cdd113b627e1a69c4dc9b2f39132acf081ea16cb3`.
Эти числа **не доказывают улучшение доставки в полной симуляции**. Среда не
моделирует локализацию, динамику MPC/PPO или ошибки восприятия. Перенос нужно
оценивать в closed-loop запуске с одинаковыми G1–G4; такие результаты следует
хранить отдельно от табличных.
