# Данные и обучение метода B (G2)

Сокращения раскрыты при первом употреблении; [полный словарь терминов](../../docs/GLOSSARY.md).

Офлайн-инструменты обучаемого метода B на Python: подготовка данных и обучение разрешены на Python, работа модели в роботе — на C++ (`CnnClassifier` в [capstone_perception](../../ros2_ws/src/capstone_perception/README.md)).

## Планировки складов

Чтобы тестовые данные не «утекали» в обучение, кадры пишутся на разных складах ([docs/EXPERIMENTS.md](../../docs/EXPERIMENTS.md)). [generate_layout.py](generate_layout.py) строит склад по сиду: робот, камера, пол, стены и свет берутся без изменений из `simulation/worlds/warehouse.wbt`, а содержимое генерируется — ряды стеллажей (вдоль x или y, длина 2–4 м, глубина 0.6–1 м, высота 1.6–2.4 м, 2–4 полки), коробки на полках, ящики, штабели поддонов и боксов на полу, **тонкие стойки** 2–5 см и **низкие препятствия** 4–15 см (трудные случаи G2), метки станций, оттенок пола и стен. Используются только модели, уже лежащие в проекте, поэтому миры загружаются без сети.

Разбиение — [splits.json](splits.json): обучение `train_0…train_2` (сиды 0–2), валидация `val_0` (1000), тест `test_0`, `test_1` (2000, 2001). Сид планировки одновременно задаёт позы и освещение при записи. Список: `python3 ml/perception/generate_layout.py --list`.

## Запись кадров

```bash
make g2-dataset LAYOUT=train_0 SAMPLES=300
make g2-dataset-splits SAMPLES=300
```

Первая команда пишет одну планировку в `data/g2/train_0/`, вторая — все планировки разбиения подряд и сразу их размечает. Без `LAYOUT` записывается основной мир `warehouse.wbt` с сидом `SEED` (`make g2-dataset SEED=0`).

Симулятор запускается без окна в быстром режиме с копией мира, где есть supervisor `dataset_recorder` ([record_dataset.py](record_dataset.py)). Для каждого кадра он:

1. ставит робота в случайную позу на складе (равномерно по полу, отступ от стен 0.5 м, случайный поворот) и задаёт случайную яркость фона и света (`--light-min`…`--light-max`, по умолчанию 0.2–1.0 — от слабого до обычного освещения);
2. ждёт 0.3 с симуляции и отбрасывает позу, если робота сдвинуло — он оказался внутри препятствия;
3. берёт следующий кадр из `/sensors/rgb`, `/sensors/depth`, `/sensors/camera_info` — **те же данные, что получает узел восприятия**: `rgb8`, глубина совмещена с цветом, `NaN` — нет измерения.

Результат — `data/g2/<RUN>/` (в Git не попадает):

| Файл | Содержимое |
|---|---|
| `frame_NNNNNN.npz` | `rgb` (uint8, 480×640×3), `depth` (float32, м, `NaN`), `world_from_base` (точная поза робота 4×4 — только для разметки и анализа), `stamp`, `light`, `sample_seed`, `sample_index` |
| `meta.json` | мир (`generated:<layout>` или имя файла), `layout_id`, `seed`, число кадров и отброшенных поз, модель камеры, `base_from_camera`, коммит Git и признак незакоммиченных изменений |

Около 0.85 МБ и 0.4 с на кадр: 200 кадров записываются примерно за полторы минуты. Позы и освещение берутся из генератора случайных чисел с сидом `SEED`, он записывается в `meta.json`.

## Разметка

```bash
make g2-labels RUN=warehouse_seed0
```

[label_dataset.py](label_dataset.py) пишет `data/g2/<RUN>/labels/frame_NNNNNN.npz` (`labels`, uint8, 480×640) и `labels/meta.json` с порогами и долями классов. Метка пикселя — по высоте его точки над полом ([labels.py](labels.py)); пол склада ровный, его высота известна точно (z = 0), поза камеры — точная из симулятора, глубина — без шума:

| Высота точки над полом | Класс |
|---|---|
| `NaN` в глубине | `255` неизвестно |
| \|h\| ≤ 2 см (`--floor-tolerance`) | `0` свободно |
| 2 см < h ≤ 1 м (`--robot-height`) или h < −2 см | `1` препятствие |
| h > 1 м (робот проезжает под этим) | `255` неизвестно |

Классы совпадают с `capstone_perception::PixelClass`. Шум и дыры глубины, тёмные кадры добавляются **ко входу сети** при обучении, а метки берутся с чистых данных — так сеть учится тому, о чём исследовательский вопрос G2: устойчивости к шуму глубины и освещению. Пороги можно менять и размечать заново без новой записи.

## Обучение

```bash
make g2-train
make g2-train TRAIN_ARGS="--epochs 40 --batch-size 8 --out ../../data/g2/models/width24 --width 24"
```

Образ `train` (Python 3.12, PyTorch 2.14.1 с CUDA 12.6, ONNX, ONNX Runtime; версии в [requirements.txt](requirements.txt)) собирается при первом запуске. Если в Docker есть видеокарта NVIDIA, `make` сам добавляет [compose.gpu.yml](../../compose.gpu.yml), иначе обучает на CPU. Чтобы Docker видел видеокарту, нужен драйвер NVIDIA (проверка — `nvidia-smi`) и один раз [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html):

```bash
sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker
docker run --rm --gpus all ubuntu:24.04 nvidia-smi
```

(пакет ставится из репозитория NVIDIA — по ссылке выше, раздел «With apt»).

- **Вход и выход сети** — [preprocess.py](preprocess.py): тензор 5 × 240 × 320 (RGB, глубина / 8 м, маска наличия глубины), на выходе логиты классов свободно / препятствие / неизвестно. `CnnClassifier` на C++ обязан повторить эту подготовку буквально.
- **Модель** — [model.py](model.py): компактный U-Net (16-32-64-128 каналов, ≈0.5 млн параметров).
- **Данные** — планировки `train` и `val` из [splits.json](splits.json); тестовые планировки обучение не читает и падает, если их передать. Модель выбирается по mIoU на валидации.
- **Аугментации только входа**: затемнение и гамма, шум глубины, растущий с квадратом расстояния, дыры в глубине, отражение. Метки остаются чистыми; там, где аугментация убрала глубину, метка становится «неизвестно» — как правило работы узла.
- **Функция потерь**: взвешенная кросс-энтропия, вес препятствия 2 — ошибка «препятствие принято за свободное» опаснее.

Результат — `data/g2/models/latest/` (в Git не попадает):

| Файл | Содержимое |
|---|---|
| `model.onnx` | модель для `CnnClassifier`, вход `input` 1×5×240×320, выход `logits` 1×3×240×320 |
| `best.pt` | веса PyTorch лучшей эпохи |
| `metrics.csv` | кривые обучения: потери, IoU классов, mIoU, доля ложно-свободных пикселей на обучении и валидации по эпохам |
| `model_card.json` | данные, параметры, лучшая эпоха и её метрики на валидации, SHA256 модели |

## Проверка на тестовых складах

```bash
make g2-eval
```

[evaluate.py](evaluate.py) прогоняет `model.onnx` через ONNX Runtime (тот же файл, что загрузит `CnnClassifier`) на тестовых планировках `test_0`, `test_1`, которые обучение и выбор модели не видели. Каждый кадр проверяется в четырёх условиях с фиксированным сидом: `clean`, `low_light` (изображение ×0.3), `depth_noise` (σ = 0.005·z² м), `depth_holes` (4 пятна и 3 % пикселей без глубины). Результат — `evaluation.csv` и `evaluation.json` рядом с моделью: IoU классов, mIoU, доля ложно-свободных пикселей, точность и полнота препятствий.

Смотрите в первую очередь на IoU препятствий и долю ложно-свободных: класс «неизвестно» сеть почти без ошибок берёт из маски глубины, поэтому mIoU завышен. Это проверка самой сети; итоговое сравнение методов A и B считается на C++ по карте занятости.

## Модель в роботе

```bash
make g2-model
```

[release_model.py](release_model.py) копирует `data/g2/models/latest/model.onnx` в пакет: `ros2_ws/src/capstone_perception/models/perception_cnn.onnx` — её по умолчанию загружает `CnnClassifier` (`method: learned`). Рядом — `perception_cnn.json`: карточка модели, результаты `evaluate.py` и SHA256 файла. Модель хранится в Git (≈ 2 МБ), поэтому метод B работает у всех сразу после клонирования, без данных и обучения.

Та же команда записывает эталон для теста C++ в `capstone_perception/test/data`: кадр `test_0/frame_000000` (RGB и глубина в мм), ожидаемые классы пикселей и, в каждом 8-м пикселе, ожидаемые вход сети и логиты, посчитанные ONNX Runtime в Python. `make test` проверяет, что C++ повторяет их ([test_cnn_classifier.cpp](../../ros2_ws/src/capstone_perception/test/test_cnn_classifier.cpp)). Модель и эталон коммитятся вместе.

## Тесты

```bash
make test
```

Запускает в том числе `python3 -m unittest discover -s ml/perception`: [test_preprocess.py](test_preprocess.py) (подготовка входа сети), [test_labels.py](test_labels.py) (разметка) и [test_generate_layout.py](test_generate_layout.py) (повторяемость по сиду, разбиение без пересечений, объекты не пересекаются и не выходят за склад, робот и камера из шаблона).

Тесты модели, аугментаций и метрик ([test_train.py](test_train.py)) требуют PyTorch и выполняются в образе `train`:

```bash
docker compose --profile train run --rm train python3 -m unittest discover
```
