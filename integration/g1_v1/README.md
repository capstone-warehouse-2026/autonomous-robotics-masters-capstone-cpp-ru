# Стартовый набор HW1 / G1 · контракт v1

Базовая карта, TF и датчики для разработки G2–G5 без запуска Webots, без робота и без ожидания финальной локализации G1. Имена и типы соответствуют [общему контракту v1](../../docs/INTERFACES.md). Целевой стек класса: Ubuntu 24.04 и ROS 2 Jazzy внутри штатного Docker Compose проекта; хост может быть Ubuntu 22.04 или 24.04. Python-фикстура предназначена только для тестов разработчика и не входит в сдаваемый C++ runtime.

## Быстрый старт на целевом стеке

Из корня репозитория, с рабочим Docker Compose:

~~~bash
bash integration/g1_v1/course_smoke.sh mock
bash integration/g1_v1/course_smoke.sh real
bash integration/g1_v1/course_smoke.sh replay
~~~

Используется сервис dev курса, без зависимых сервисов и без запуска Webots. Режим real собирает только пакет capstone_localization в новом временном каталоге (нужен checkout с реализацией G1). Режим replay записывает новый bag и проверяет его в отдельном DDS-домене. Он не подменяет серверы планирования или управления.

Ожидаемый ответ: PASS G1 v1: 10 topics, 6 TF edges, advancing clock. Проверяются доставка с заданным QoS, frame/stamp, формат карты, скана и изображений, конечность ковариаций и единственный издатель карты, часов и TF. Проверка ограничена по реальному времени. Это smoke-тест связи, не тест точности, частоты под нагрузкой, отказов или безопасности.

Проверенный ранее прогон использовал отдельную ограниченную конфигурацию Compose,
а не холодную сборку конкретно этой команды `course_smoke.sh`. Если только
`real` заканчивается `Permission denied` при запуске уже собранного бинарника,
проверьте, не смонтирован ли `/tmp` в контейнере как `noexec`: скрипт
собирает туда. Не меняйте защиту хоста для обхода; используйте штатные
`make build PKG=capstone_localization` и `make test PKG=capstone_localization`
и сообщите о различии окружения. `mock` не собирает C++ в `/tmp`.

### Разработка в отдельных терминалах

В одной среде Ubuntu 24.04 / Jazzy (например, в двух оболочках одного dev-контейнера) настройте оба терминала одинаково:

~~~bash
source /opt/ros/jazzy/setup.bash
unset ROS_LOCALHOST_ONLY ROS_STATIC_PEERS
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST ROS_DOMAIN_ID=191  # свободный домен 170..224
~~~

В первом терминале: python3 integration/g1_v1/fixture.py mock. Во втором запускайте свой узел с use_sim_time:=true. Для позднего подключения к /map и /tf_static используйте reliable + transient_local. Не запускайте fixture в том же домене, где работает Webots, другая копия fixture или реальный робот. Fixture не подписывается на /cmd_vel и не публикует ground truth.

| Группа | Что можно подключать сейчас | Ограничение |
|---|---|---|
| G2 | /sensors/rgb, /sensors/depth, /sensors/camera_info, TF камеры и робота | RGB-D синхронизированы по stamp, но содержат однотонные кадры с постоянной глубиной 2 м. Они не изображают склад и не подходят для оценки модели. |
| G3 | /map, /localization/pose, TF | Тестовая карта свободной прямоугольной комнаты 8 × 8 м с занятыми границами; не складская SLAM-карта. Для препятствий нужны собственные фикстуры или G2. |
| G4 | /state/odom, /sensors/scan, TF | Поза меняется по заданной траектории и не реагирует на команды; это не closed loop и не проверка аварийной остановки. |
| G5 | /state/odom, /localization/pose, /clock | Планирование и управление нужно подключить отдельно или подменить своими тестовыми action-серверами. |

Mock публикует wheel/IMU/state odom и часы с шагом 20 мс (50 Гц по штампам), scan/RGB-D/map pose с шагом 100 мс (10 Гц по штампам); карту и статический TF один раз с сохранением последнего значения. Оси и единицы в общем контракте. Переход к настоящей G1 не требует переименований: fixture.py sensors отключает mock-выходы и два динамических TF. Не включайте одновременно mock и настоящий G1.

## Опциональный локальный запуск и C++ нода

На Ubuntu 24.04 с установленной Jazzy можно выполнить bash integration/g1_v1/smoke.sh mock без Docker. Пакеты rclpy, rosbag2, стандартных сообщений и TF должны быть установлены. Скрипт по умолчанию использует Jazzy. Если подлинная C++ нода G1 уже собрана в Jazzy, bash integration/g1_v1/smoke.sh real использует ros2_ws/install или каталог из G1_INSTALL_PREFIX. Стройте Humble и Jazzy в разных каталогах.

На хосте с Ubuntu 22.04 / Humble доступна только вспомогательная проверка: G1_ROS_DISTRO=humble bash integration/g1_v1/smoke.sh mock. Для Humble вместо ROS_AUTOMATIC_DISCOVERY_RANGE используйте ROS_LOCALHOST_ONLY=1. Humble не является целевой платформой класса; сохранённый Humble bag не заменяет новую проверку формата записи под Jazzy.

В режиме real классическая C++ нода публикует /state/odom, /localization/pose и динамические TF; fixture поставляет только входы. Текущая G1 публикует map pose на каждом wheel tick, а не с номинальными 10 Гц; потребителям нельзя полагаться на ровно 10 Гц. Этот запуск не проверяет Webots, готовность SLAM, качество A/B или production-ready обработку отказов.

## Записать и переиграть rosbag

Короткую проверяемую запись создаёт replay_smoke.sh. Ниже ручной вариант для записи, которую вы хотите сохранить.

После запуска mock и настройки окружения, как выше:

~~~bash
ros2 bag record -s sqlite3 -o g1_v1_mock \
  --qos-profile-overrides-path integration/g1_v1/bag_qos.yaml \
  /clock /map /tf_static /tf /sensors/wheel_odom /sensors/imu /sensors/scan \
  /sensors/rgb /sensors/depth /sensors/camera_info /state/odom /localization/pose
~~~

Остановите запись Ctrl+C через несколько секунд, проверьте ros2 bag info g1_v1_mock, затем остановите fixture. Для воспроизведения:

~~~bash
ros2 bag play g1_v1_mock --qos-profile-overrides-path integration/g1_v1/bag_qos.yaml
~~~

Для входного bag без выходов включите sensors и уберите из команды записи /state/odom, /localization/pose и /tf; эти три потока создаст C++ нода. Не добавляйте --clock к проигрыванию (в bag уже записан /clock). Запускайте потребителей **до** проигрывания; /map и /tf_static сохраняются только пока проигрыватель запущен. После окончания начните новый экземпляр потребителя или выполните контролируемый reset; не оценивайте поведение при reset через --loop.

## Что ещё должна передать G1

Отдельно готовы [частичная карта склада для G3](../../ml/localization/g3_train0_map.md) и [диагностический отчёт классического replay](../../ml/localization/train0_scoring_readout.md). Не подключайте к ним позы синтетического mock: у них другая карта и зарегистрированный старт. Частичную карту проверяли как артефакт и как вход для позднего подписчика, не как результат планировщика. Одиночный проезд не заменяет квалификацию карты, калибровку, held-out сценарии и сравнение A/B. Стенд v1 остаётся самостоятельным, не требует этих артефактов и не запускает готового робота.
