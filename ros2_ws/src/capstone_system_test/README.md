# Независимая проверка физической интеграции G5

`system_evaluator` получает эталонную позу **только для проверки**. G5, Nav2,
локализация и управление не подписываются на `evaluation/*`.

Стенд использует физический Webots, колёсные энкодеры, LiDAR, AMCL, Navfn A* и
контроллер Nav2. Это базовая интеграционная навигация для G5, не реализация
сравнительных заданий G1–G4. Тестовые action-серверы здесь не используются.

Сценарий `scenarios/deliveries.yaml` содержит две доставки между точками
(-3,0) и (3,0). Стеллаж x∈[-0.5,0.5], y∈[-2,2] перекрывает прямой путь.
Планировщик и физический робот должны объехать его с учётом радиуса.

Evaluator записывает `trajectory.csv` и `plans.csv`. После каждого успешного
эпизода появляется `episode_1.yaml`, `episode_2.yaml`, …; общий `audit.yaml`
сохраняется при завершении. Exit code0 означает прохождение всех проверок:

- Достаточно фактических измерений ground truth и ненулевое физическое движение.
- Есть опубликованный Nav2 путь, у которого прямая от старта до цели пересекает
  расширенный стеллаж, а каждый сегмент пути проходит вне него. Просто длинный
  маршрут не считается доказательством объезда.
- Ни один отрезок истинной траектории не пересекает расширенный стеллаж;
  отсутствие физических контактов подтверждено отдельным свежим потоком Webots.
- Каждое событие `picked`/`delivered` сопоставлено с измеренной физической позой
  в тот же момент. Допустимое отличие от станции0.35м; ближайшее измерение должно
  быть не старше0.15с simulation time. Для `completed` нужны все заявки manifest.
- После terminal-состояния истинная поза и колёсная одометрия подтверждают остановку
  непрерывно хотя бы0.3с simulation time.
- В режиме отмены проверяется принятие `mission/cancel`, затем именно `cancelled`
  и физическая остановка. Ответ сервиса сам по себе остановку не подтверждает.
- Для двух эпизодов требуется регресс времени **между** завершёнными эпизодами;
  первоначальный reset не засчитывается.

Evaluator запускается до миссии и работает дольше runner, чтобы успеть проверить
остановку. Обязательные параметры: `manifest_path`, `event_log`, `output_directory`.

```bash
ros2 run capstone_system_test system_evaluator --ros-args \
  -p use_sim_time:=true \
  -p manifest_path:=/absolute/path/deliveries.yaml \
  -p event_log:=/absolute/path/run/events.csv \
  -p output_directory:=/absolute/path/run/physical \
  -p wall_timeout:=300.0
```

Для проверки отмены добавить `expected_terminal:=cancelled`,
`cancel_after_distance:=1.0`, `require_detour:=false`: отмена поступит после одного
метра фактического движения. Для повторного reset использовать `required_episodes:=2`
и начинать следующий эпизод лишь после появления `episode_1.yaml`.

Полный запуск организует `scripts/run_g5_system.py`. Геометрические и временные
проверки тестируются `make test PKG=capstone_system_test`. Unit-тесты отдельно
проверяют пересечение редкого длинного отрезка со стеллажом, касание границы,
учёт радиуса, настоящее отличие объезда от просто длинного пути и отсутствие
ground truth около события обслуживания.
