# Физический адаптер Webots для интеграции G5

Отдельный C++ внешний контроллер Webots R2025a. Использует настоящую динамику мира,
моторы, PositionSensor колёс и OpenGL LiDAR. Не заменяет движение интерполяцией позы
и не реализует задания G1–G4: это стенд для проверки G5 с Nav2.

`WEBOTS_HOME` указывает на распакованный Webots. При сборке без SDK пакет собирает
только математические тесты; для физического запуска нужно пересобрать с SDK.
Общие команды установки и запуска находятся в корневом README/Makefile.

Для нескольких роботов предусмотрены параметры `publish_clock`, `absolute_time`
и `enable_reset`. По умолчанию однороботный режим сохранён. Флот использует
абсолютное время Webots, один общий издатель часов и запрещает индивидуальный
reset. Схема namespace и точные команды — в [simulation/fleet](../../../simulation/fleet/README.md).

Внешний контроллер подключается командой:

```bash
"$WEBOTS_HOME/webots-controller" --robot-name=g5_robot --port=1234 \
  ros2_ws/install/capstone_webots_bridge/lib/capstone_webots_bridge/webots_bridge
```

Сам Webots должен открыть `simulation/integration/warehouse.wbt` на том же порту.
В режиме без окна требуется Xvfb: LiDAR использует настоящий рендеринг глубины,
поэтому отсутствие главного 3D-окна не означает отсутствие OpenGL.

## Контракты

- `cmd_vel`, `TwistStamped`, reliable depth 1: только выход safety monitor,
  `frame_id=base_link`. Устаревшие по sim/steady времени (>300 мс), будущие,
  нечисловые и превышающие ограничения команды дают нулевую скорость моторов.
- `state/odom`, reliable depth 5, и `sensors/wheel_odom`, sensor QoS: 50 Гц.
  Источник — разность измеренных углов колёс; точная интеграция дуги.
  После reset начало odom равно `(0,0,0)` независимо от координат мира.
- TF `odom → base_link`: из той же энкодерной одометрии.
- `sensors/scan`, sensor QoS: 10 Гц, 360 лучей, полный круг, 0.05–12 м,
  `lidar_link`. Неподвижный слой измеряется одновременно; порядок лучей обращён
  из Webots left-to-right в положительное направление угла ROS.
- Статический TF `base_link → lidar_link`: `(0,0,0.25)`, единичное вращение.
- `clock`: только физические шаги Webots. Один шаг — 20 мс.
- `evaluation/ground_truth`, `Odometry`, map, reliable depth 10: реальная поза
  Supervisor, **только для evaluator**. В одометрию, TF и навигацию не поступает.
- `evaluation/contact`, `Bool`, reliable depth 10: контакт тела/колёс с объектом
  выше 4 см над полом. В данном мире все стены/стеллажи выше этого уровня;
  постоянные контакты колёс и опор с полом исключены. Это критерий данного мира,
  а не универсальный классификатор контактов для произвольных объектов.

## Сброс

`simulation/reset`, `std_srvs/Trigger`, восстанавливает физическую позу и суставы
из начального состояния Supervisor, обнуляет скорости, историю энкодеров и
последнюю команду. `/clock = wb_robot_get_time() - epoch`; epoch обновляется при
reset, поэтому часы эпизода начинают отсчёт заново без перезапуска Webots.
Ответ сервиса отправляется после следующего физического шага и публикации новых
часов/одометрии. Старые команды с прежними stamp отвергаются.

Сервис не сбрасывает AMCL, Nav2 или G5. Оркестратор сначала останавливает автономию,
затем сбрасывает симулятор и состояния остальных компонентов, восстанавливает
начальную оценку AMCL и ждёт свежих входов. Это предотвращает продолжение старой
цели после изменения odom.

## Геометрия стенда

Мир и карта находятся в `simulation/integration/` и устанавливаются в
`share/capstone_webots_bridge/worlds`. Границы карты: x=[−6,6], y=[−5,5],
разрешение 0.05 м. Стены занимают крайние 0.1 м. Главный стеллаж:
x=[−0.5,0.5], y=[−2,2]. Дополнительный: x=[−4.6,−3.4], y=[2.75,3.75].

Робот стартует в map `(−3,0,0)`. Радиус корпуса 0.28 м, колёс 0.0985 м,
колея 0.4044 м. Это простая физическая дифференциальная платформа с размерами
привода TIAGo Base; она не является точной динамической моделью TIAGo.
Карта нарисована по статической геометрии мира; ground truth в runtime не нужен.
Переход из `(−3,0)` в `(3,0)` требует объезда настоящего коллизионного стеллажа.

## Проверки

`test_wheel_odometry` проверяет движение прямо/по дуге, reset, нечисловые измерения
и защиту от устаревших/будущих команд. `bridge_probe` — отдельная физическая проверка
драйвера: настоящие расстояния LiDAR, движение по команде, сопоставление энкодеров
с evaluator, остановка watchdog и физический reset. Запускать её в отдельном
ROS_DOMAIN_ID без Nav2 и safety monitor: probe сам публикует тестовые `cmd_vel`.
Её успешность не является проверкой автономной доставки; для этого служит
`capstone_system_test` с настоящими Nav2 и G5.

Первоисточники формата датчика и состояния Supervisor:
[Webots LiDAR](https://cyberbotics.com/doc/reference/lidar),
[Webots Supervisor](https://cyberbotics.com/doc/reference/supervisor).

Воспроизведение отдельного probe после `make g5-system-build`:

```bash
scripts/run_bridge_probe.sh results/bridge-probe 186
```

Скрипт запускает собственные Webots/Xvfb и внешний контроллер, затем проверку,
останавливает процессы и сохраняет `audit.json` с измерениями и SHA256 исходников,
мира и бинарных файлов. Каталог результата должен быть новым. `G5_INSTALL_DIR`
позволяет указать другой `colcon --install-base` для изолированной сборки.

Зафиксированный прогон: [bridge-probe](../../../experiments/g5/webots-nav2/bridge-probe/audit.json).
Физическое смещение 0.855997 м, энкодерное 0.855882 м; после прекращения команд
скорость корпуса −0.000004 м/с, скорость энкодеров 0, контактов с препятствиями нет.
Сервис reset вернул подтверждение после физического шага; поза и odom вернулись
к начальным значениям. Логи мира не содержат `ERROR:`. Это отдельная проверка
драйвера, не результат автономной доставки.
